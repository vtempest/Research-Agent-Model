QwkSearch doesn't have its own crawler. It queries many existing engines in
parallel, merges the results, and hands the top ones to a language model along
with the extracted page text. That means coverage comes from the engines you
enable, and answer quality comes from the extraction step.

## Categories

Engines are registered under one or more categories. Each category carries a
default scoring weight used when results from several engines are merged — a
paper from an academic engine outranks a forum post for the same query.

| Category | Covers | Default weight |
|---|---|---|
| `general` | General web search | 1.0 |
| `academic` | Papers, preprints, citations | 1.3 |
| `it` | Programming and IT resources | 1.2 |
| `news` | News search | 1.1 |
| `specialized` | Domain-specific engines | 1.1 |
| `images` | Image search | 1.0 |
| `videos` | Video search | 1.0 |
| `maps` | Maps and locations | 1.0 |
| `music` | Music search | 1.0 |
| `files` | File search | 1.0 |
| `shopping` | Shopping and products | 1.0 |
| `social` | Social media content | 0.9 |
| `torrents` | Torrent search | 0.8 |

The full registry lives in
[`packages/search-web-api`](https://github.com/OpenSourceAGI/qwksearch-research-agent/tree/master/packages/search-web-api),
which is published to npm as `search-web-api` and usable on its own.

## Choosing engines

Open **Settings → Search** to enable or disable individual engines. Two API
routes back that screen:

```http
GET  /api/search/engines          # every engine, grouped by category
GET  /api/search/engines/status   # which ones you have enabled
POST /api/search/engines/status   # save your selection
POST /api/search/engines/test     # check which are currently responding
```

Engines go down, rate-limit, or change their markup. `POST /api/search/engines/test`
runs a probe query against each one so you can spot the dead ones instead of
silently getting fewer results.

## Running a search

```http
GET /api/agent/search?q=your+query
```

This is the meta-search endpoint (SearXNG-backed) — raw results, no language
model. For a cited answer, use the streaming chat endpoint described in
[Chat & research agent](/docs/chat).

Autocomplete for the search box:

```http
GET /api/agent/autocomplete?q=partial+quer
```

## Privacy mode

Searches are saved to your history so you can come back to them and so the
agent can reuse context. Privacy mode turns that off for a session: nothing is
written to your chat history, and no memory is stored. Signed-out use never
writes history in the first place.

## Self-hosted metasearch

If you'd rather not depend on public engine endpoints, the repo ships a
SearXNG deployment config in
[`packages/searxng-search-cloudflare`](https://github.com/OpenSourceAGI/qwksearch-research-agent/tree/master/packages/searxng-search-cloudflare).
Point your instance at it and every query stays inside infrastructure you
control. See [Self-hosting](/docs/self-hosting).
